# Offline-first data (Task 2)

**Why**: the UI reads only the local Drift database, so every screen works in airplane mode from the first launch. A server, if any, only refreshes that database.

- `core/database`: Drift tables (`tables.dart`) and `AppDatabase`. Schema history is documented in `app_database.dart`: v1 catalog tables, v2 `cart_items`. `onUpgrade` runs each step once, in order (tested by upgrading a hand-built v1 database).
- Seed: `assets/seed/seed.json` is parsed into `CatalogSnapshot` (freezed + json_serializable) and written by `CatalogWriter` in one transaction. `SeedLoader` runs on launch and only writes when nothing is seeded or the bundled `version` is newer. The same snapshot shape is what the optional mock server returns, so seed and refresh share one writer.
- Catalog data is *replaced*, not merged (the server is the authority); user data (cart) is never touched by a refresh.
- Repositories (`features/*/data/drift_*_repository.dart`) expose `Stream`s via Drift `watch`, so the UI updates automatically when a refresh writes new rows.
- One member record (`members` table, `MemberRepository`) feeds Home and Rewards: Silver, 500 points to Gold, 680,000 total points.
- Images: each entity has `imageAsset` (bundled PNG, always works offline) and optional `imageUrl` (remote, cached on disk). Placeholder art is generated by `tool/build_seed_assets.sh` (SVG sources in `tool/seed_art`, PNGs in `assets/images`).

Tests: `test/core/database/seed_and_repositories_test.dart`.

## Refresh, connectivity and the optional server
- `ConnectivityService` combines connectivity_plus (interface up) with a real reachability check (DNS lookup), so Wi-Fi without internet and airplane mode both read as offline. `isOnlineProvider` streams the state; `OfflineBannerLayout` (used by the tab shell) shows a small banner while offline.
- `CatalogSync.refresh()`: no-op without a server; `NetworkFailure` while offline; otherwise fetch + `CatalogWriter.replaceAll`. Concurrent callers share one in-flight request.
- `SyncController` refreshes in the background when the device comes back online (and on launch if online). Screens call it for pull-to-refresh. Failures never block the UI, which keeps showing local data.
- Server is opt-in: `--dart-define=API_BASE_URL=http://localhost:8080` (Android emulator: `http://10.0.2.2:8080`). Start it with `dart run tool/mock_server/bin/server.dart` (no packages). It serves `/v1/health`, `/v1/catalog` in a `{data, error, meta}` envelope, and `/images/*.png`; each catalog fetch bumps the member's notification count so refreshes are visible. `?fail=1` returns the error envelope, `?delay=ms` adds latency.
- Dio (`core/network`): timeouts, `RetryInterceptor` (idempotent requests only, exponential backoff, max 2 retries), debug-only logging. No auth or token refresh: the data is public.
- Cleartext http is allowed only for local networking on iOS (`NSAllowsLocalNetworking`) and in Android debug/profile builds, so release builds stay https-only.

Tests: `test/core/sync/catalog_sync_test.dart`, `test/core/network/retry_interceptor_test.dart`.
